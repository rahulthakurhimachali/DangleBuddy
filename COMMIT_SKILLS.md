# Commit Message Guidelines

Follow these rules whenever creating Git commits.

## 1. Commit Message Format

Always use a conventional commit type:

* `feat:` — Add a new feature
* `fix:` — Fix a bug or incorrect behavior
* `chore:` — Maintenance, configuration, dependencies, tooling, etc.
* `refactor:` — Code restructuring without changing behavior
* `docs:` — Documentation changes
* `test:` — Adding or updating tests
* `perf:` — Performance improvements
* `build:` — Build system or dependency changes
* `ci:` — CI/CD changes

Use the format:

```text
type: short description
```

Examples:

```text
feat: add interstitial ad support
fix: prevent duplicate feed events
chore: update Expo dependencies
refactor: simplify auth context
test: add coverage for feed tracking
```

## 2. Keep Messages Under 72 Characters

The entire commit subject must be **72 characters or fewer**.

Keep the message short, clear, and focused on what changed.

Good:

```text
fix: prevent duplicate feed view events
```

Bad:

```text
fix: update the feed rendering logic to prevent duplicate events from being triggered
```

If the change requires more explanation, use a commit body rather than making the subject excessively long.

## 3. Never Mention AI or Coding Agents

**Never use phrases such as:**

```text
Co-authored-by: Codex
Co-authored-by: Cursor
Co-authored-by: Claude
Co-authored-by: ChatGPT
Generated by AI
Generated with Claude
Generated with Cursor
Generated with Codex
```

Do not add AI tools, coding agents, or assistants as co-authors.

The commit should represent the project's actual authorship.

## 4. Preserve Original Authorship

When modifying an existing project or repository:

* Keep the original author's copyright notices.
* Do not replace the original author with yourself.
* Do not claim ownership of code that was originally written by someone else.
* Do not rewrite existing attribution unless the project's license explicitly permits or requires doing so.
* When making changes, attribute the commit to the actual person making the change according to the repository's normal Git configuration.

For MIT-licensed projects, retain the original MIT license and copyright notice when required by the license.

## 5. One Commit = One Logical Change

Keep commits focused.

Good:

```text
feat: add interstitial ad support
fix: handle missing ad configuration
test: add interstitial rendering tests
```

Avoid combining unrelated changes:

```text
feat: add ads, refactor auth, update dependencies, fix tests
```

## 6. Use Imperative, Concise Descriptions

Prefer:

```text
fix: handle missing user avatar
feat: add feed depth tracking
chore: update React Native version
refactor: simplify ad configuration
```

Avoid:

```text
fix: fixed the avatar issue
feat: added a new feed tracking feature
chore: updated some dependencies
```

## 7. Final Checklist

Before creating a commit:

* [ ] Use a conventional commit type.
* [ ] Keep the subject ≤ 72 characters.
* [ ] Keep the message concise and specific.
* [ ] Don't mention Codex, Cursor, Claude, ChatGPT, or other AI tools.
* [ ] Don't add AI co-authorship.
* [ ] Preserve original authorship and copyright notices.
* [ ] Keep the commit focused on one logical change.
* [ ] Don't modify license/attribution information unnecessarily.
